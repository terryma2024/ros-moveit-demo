# SO-101 Head pre-ARM readiness and scoped close design

Status: proposed protocol design for review, 2026-10-09. This document authorizes no implementation or runtime claim. It concerns the simulated Head file protocol in the current worktree only.

## Purpose and evidence boundary

Case `900009` reached the native neck controller's first `STOP_PROOF_BEFORE` check and was refused. No generation was established. The later `PRIMARY_FAULT` close named the intended nonzero generation, while `ControllerGoalAdmission::revoke_generation` required equality with its stored generation, still zero. The close therefore had no validated ACK and the attempt remained `UNKNOWN`, even though separate physical Stop and child exit checks passed. The original stop witness's specific rejection reason was not captured and remains **NOT CONFIRMED**. A controlled later run proved that one clock ordering can produce the same boundary, but that does not attribute the original event to that mechanism or establish recurrence of the old negative age bug. The diagnostic restart batch reached 42 native ARM attempts and 84 stop proof calls, all of which passed. It also found distinct ARM channel deadline, admission resume, and environment scope failures. Diagnostic instrumentation may affect scheduling. The causal report path is recorded under Evidence below.

The change should wait for a native proof ready state before sending exactly one ARM, preserve native ARM's two independent stop checks, and make a never established generation close provable without pretending an ARM ACK occurred. A readiness reply is a snapshot, not a lease. ARM may still refuse after readiness changes. No query or close path may authorize goal ingress.

## Selected approach

Extend the two existing authenticated Unix sockets. The primary socket gets a read only `PREARM_STATUS` request and a Head specific diagnostic ARM request whose server calls the same ARM routine as today's opcode 3. The independently provisioned `PRIMARY_FAULT` socket gets a read only bootstrap identity query and `CLOSE_SCOPED`, an atomic, incarnation-bound close that distinguishes a stored generation of zero from a matching armed generation. Keep legacy opcodes and replies for their existing callers. Do not add a service, ROS action, retrying ARM worker, or a second owner.

Two other approaches are weaker here. Polling Python `/joint_states` cannot prove the native `ControllerStopWitness` window, and a stopped ROS neck need not mean the controller's 51 consecutive samples passed. Repeating ARM after a refusal can cross a generation boundary and cannot resolve an uncertain 50 ms transport outcome. A main socket identity query or opcode 4 cannot serve as pre-ARM readiness: both currently require an active exclusive generation.

## Native state and proof evaluation

The current diagnostic source already provides `ControllerStopWitness::checked_proof()` with a bounded `Snapshot`: current `RejectionReason`, separate historical `ResetReason`, sample count, lost state, first and last observations, evaluation time, and failing indices. The runtime protocol must consume that same checked result. `INCOMPLETE` is the current evaluation result after an invalid sample resets the window; `last_reset_reason` describes the earlier reset and must not replace `INCOMPLETE`. The monotonic evaluation clock stays inside the witness lock, after the window is fixed. The existing predicate order and comparison operators remain unchanged.

One typed `ControllerStopEvaluation` at `BrokerOwnedTrajectoryController` wraps `checked_proof()` and preserves the current outer order: `witness_active` before; monitored joint scope; active or nonholding goal before; the witness evaluation; `witness_active` after; active or nonholding goal after. Outer failures have distinct codes (`INACTIVE_BEFORE`, `JOINT_SCOPE`, `ACTIVE_BEFORE`, `INACTIVE_AFTER`, `ACTIVE_AFTER`) even when the witness itself passes. Both legacy opcode 3 and new opcode 6 call this one routine before and after `gate.arm`; the legacy bool behavior and 16 byte reply stay unchanged. The `ControllerReservationSocket::StopProof` callback becomes a typed result carrying the decision and a fixed diagnostic record. The record receives a unique, increasing `evaluation_id` from that controller service incarnation before the wrapper checks, so even an outer failure is attributable. The wrapper's existing goal invalidation still occurs at the same before or after branch.

The witness mutex protects only the unchanged fixed 51-sample, at most five-joint evaluation and bounded POD snapshot copy. It must never cover allocation, string formatting, logging, socket I/O, gate locking, callbacks, or the controller's outer checks. The gate mutex must never be acquired while holding the witness mutex. Native refusal logging formats the returned copy after both locks are released. `observe()` keeps its nonblocking lock attempt and reset semantics. A separate saturating lock-loss counter is sampled into the result; it cannot affect the proof predicate. A later inspection of mutable witness state cannot be reported as the reason for an earlier call.

The 51 continuous samples, exact 2 ms simulation step, exact reference-position equality across the window, 200 ms age limit, and 0.002 rad/s measured and reference velocity limits remain unchanged. The readiness query calls the same controller-level evaluator as ARM and reports only that call. It has no effect on the admission gate. The native ARM routine still evaluates stop before `gate.arm(generation)` and again after it, in that order. A failure after `gate.arm` leaves the stored generation equal to the requested generation but closes the gate; that case must use the matching armed close, regardless of the public `generation()` accessor returning zero for a closed gate. Legacy stale-generation ARM refusal retains its current gate-close behavior. The different-generation no-mutation guarantee below applies to the new scoped close, not ARM.

Add a gate read method for `prearm_scope(desired_generation)` and an atomic `close_scoped(desired_generation, expected_role, expected_incarnation, expected_boot)` method. Both use the gate mutex. The read method reports the immutable service role/incarnation/boot, stored generation, revocation latch, clock fault, and whether the desired nonzero generation is strictly greater than the stored generation. It never sets a generation or opens a gate. It must use the configured identity, not `service_identity()`, which intentionally returns no identity until exclusive mode. A clock fault or latched revocation makes readiness terminally refused. The native ARM still decides final eligibility using its existing clock and generation rules.

`close_scoped` first compares the expected role, incarnation, and boot with the gate's configured identity under the same lock that would set the latch. An identity mismatch returns `REJECT_IDENTITY` with **no mutation**, even when both services run in the same PID with the same provision bytes. A Head attempt pins the identity learned from the fault socket's bootstrap query independently of `_armed_identity`, then requires the main readiness identity to equal it. Without a validated bootstrap identity, no `CLOSE_SCOPED` is sent: the attempt performs physical cancel and owned retirement, records native seal `UNPROVEN` and terminal `UNKNOWN`, and cannot ARM. This policy covers failure or SIGTERM before the first valid query. With a matching identity, the gate applies this table under one lock:

| Stored generation at close | Gate action | Native result |
| --- | --- | --- |
| `0` | Set the controller owned revocation latch, close the gate, leave stored generation `0` | `NOT_ARMED_CLOSED` |
| Exactly desired generation | Set the same latch and close the gate, including a gate closed by `STOP_PROOF_AFTER` | `ARMED_CLOSED` |
| Any other nonzero generation | Do not change gate or latch | `REJECT_GENERATION` |

The latch survives gate recreation within the controller object and makes any later ARM fail. These actions are linearized under the mutex against ARM, so a zero generation receipt cannot race with a later successful ARM. The receipt does not assert physical Stop, cancellation, process exit, or completed retirement. An invalid peer, capability, frame, role, or identity produces no successful receipt. For a syntactically valid `SOPC` from the exact expected OS peer, a stale capability, different service identity, or different generation returns no success and leaves the replacement gate and latch unchanged. A stale capability may receive no reply; Python still records seal `UNPROVEN`. This narrowly scopes the new opcode's rejection behavior so provision rotation cannot let an old request fault-revoke a new gate. Malformed frames and unexpected peers retain the existing fail closed security handling. Response serialization failure, write failure, or timeout after a valid scope rejection must return from that branch without falling through to unconditional `close_gate()` or `fault_revoke()`.

## Wire contract

All integer fields below are big endian; signed timestamps and indices use two's complement. Requests use the existing four byte body length prefix and the authenticated, mode `0600` Unix socket. Both ends check `SO_PEERCRED` uid, pid, and process start ticks, private parent ownership, exact capability bytes, path, role, and the applicable exchange deadline before accepting a reply. A PID/start tick match alone never authenticates the service incarnation. No result is inferred from a disconnected or partial exchange.

`ProofRecord` is a fixed 80 byte suffix returned from the **same controller-level evaluation** that made a readiness or ARM decision. Its exact layout is `evaluation_id:u64`, `wrapper_reason:u8`, `witness_rejection:u8`, `last_reset_reason:u8`, `flags:u8`, `sample_count:u16`, `failing_sample_index:i8`, `failing_joint_index:i8`, `last_reset_joint_index:i8`, `reserved_zero:u8`, `cumulative_observation_lock_losses:u32`, `reserved_zero:u16`, then `first_sequence:u64`, `last_sequence:u64`, `first_sim_time_ns:i64`, `last_sim_time_ns:i64`, `first_received_ns:i64`, `last_received_ns:i64`, `evaluated_ns:i64`. `flags` bit 0 means a witness snapshot exists, bit 1 means `lost`, and bit 2 means samples exist; other bits are zero. Index `-1` means no failing index. The reason code maps one-to-one to the existing `ControllerStopWitness::RejectionReason` and `ResetReason` names plus the five controller wrapper branches; `PASS` and `NOT_EVALUATED` have distinct codes. A response made without a controller evaluation uses ID zero, `NOT_EVALUATED`, flags zero, and zero sample/time fields. A wrapper failure before calling the witness has a nonzero ID and no witness snapshot. A wrapper failure after calling it keeps that call's snapshot. The controller copies the record while evaluating, then formats it after releasing locks. Replies and persisted traces preserve the fixed fields, including separate current rejection and last reset reason; no later witness read may fill a missing field.

Freeze the `wrapper_reason` codes as `PASS=0`, `INACTIVE_BEFORE=1`, `JOINT_SCOPE=2`, `ACTIVE_BEFORE=3`, `INACTIVE_AFTER=4`, `ACTIVE_AFTER=5`, `WITNESS_REJECT=6`, `NOT_EVALUATED=7`. Freeze witness rejection codes in current source order as `NONE=0`, `LOST=1`, `INCOMPLETE=2`, `NEGATIVE_NOW=3`, `NONCONSECUTIVE=4`, `FUTURE_SAMPLE=5`, `STALE_SAMPLE=6`, `REFERENCE_CHANGED=7`. Freeze reset codes as `UNKNOWN=0`, `NONE=1`, `EXPLICIT_RESET=2`, `NONBLOCKING_INVALIDATION=3`, `OBSERVATION_LOCK_LOSS=4`, `ZERO_SEQUENCE=5`, `INVALID_SIM_TIME=6`, `INVALID_RECEIVED_TIME=7`, `JOINT_SCOPE=8`, `NOT_HOLDING=9`, `ACTIVE_GOAL=10`, `NONFINITE_MEASURED_POSITION=11`, `NONFINITE_MEASURED_VELOCITY=12`, `NONFINITE_REFERENCE_POSITION=13`, `NONFINITE_REFERENCE_VELOCITY=14`, `MEASURED_VELOCITY=15`, `REFERENCE_VELOCITY=16`, `SEQUENCE_GAP=17`, `SIM_TIME_GAP=18`, `RECEIVED_TIME_REGRESSION=19`. Encode `gate_reason:u16` as `NONE=0`, `CLOCK_INVALID=1`, `ZERO_GENERATION=2`, `NONINCREASING_GENERATION=3`, `CLOCK_FAULT=4`, `REVOCATION_LATCHED=5`, `SERVICE_IDENTITY_UNAVAILABLE=6`; report the first branch in the existing gate decision order. Any unknown code, invalid flag combination, or mismatched status/reason is a malformed reply, never a success.

* Fault `BOOTSTRAP_IDENTITY`: 62 byte body, `SOPQ` magic, version `1`, opcode `2`, 32 byte fault capability, nonzero desired generation, then 16 zero bytes. Its length framed `SOPI` version `1` reply carries status (`AVAILABLE=0`, `REJECT_SCOPE=1`), role, zero reserved byte, desired generation (`u64`), stored generation (`u64`), then length prefixed incarnation and boot strings. Maximum body is 154 bytes. It reads the configured service identity before ARM and changes no gate, latch, or ingress state. A complete authenticated result is pinned by `NativeRevocationClient` and `HeadLocalRuntime` before the first main readiness query. Bootstrap failure prevents ARM; it does not authorize a close for an unlearned identity.
* Main `PREARM_STATUS`: 62 byte body, `SOGR` magic, version `1`, opcode `5`, 32 byte main capability, nonzero desired generation, then 16 zero bytes. Its length framed reply is `SOPR`, version `1`, status byte (`READY=0`, `NOT_READY=1`, `REJECT_SCOPE=2`), role byte (`NECK=3`), one zero reserved byte, desired generation (`u64`), stored generation (`u64`), gate reason (`u16`), incarnation length (`u8`) and ASCII bytes, boot length (`u8`) and ASCII bytes, followed by one `ProofRecord`. Each identity field is 1–64 printable ASCII bytes. Maximum body is 236 bytes. `READY` requires an eligible gate and a passing controller evaluation with a witness snapshot; `NOT_READY` includes the exact current wrapper/witness result. A well formed not ready reply leaves gate, latch, and ingress state unchanged. Rejects, malformed replies, changed identity, and transport failures fail the attempt rather than being polled as not ready.
* Main diagnostic ARM: the same 62 byte body shape with opcode `6`, and exactly one request per attempt. The server uses the same routine as legacy opcode `3`, with unchanged before/gate/after ordering and unchanged side effects. Its fixed 104 byte `SOAR` version `1` reply carries status (`ACK=0`, `REJECT=1`), role, phase (`NONE=0`, `STOP_BEFORE=1`, `GATE_ARM=2`, `STOP_AFTER=3`), desired generation (`u64`), gate reason (`u16`), six zero reserved bytes, then one `ProofRecord`. On `STOP_BEFORE` or `STOP_AFTER`, the record belongs to the failed call. On `GATE_ARM`, it belongs to the preceding successful before proof and the gate reason names the failed ARM predicate. On `ACK`, it belongs to the successful after proof. A native refusal emits the same phase, gate reason, evaluation ID, and bounded proof record in failure only logging after replying. An `ACK` requires `NONE`, gate reason zero, and a passing after record; `REJECT` never counts as ARM. If the request, reply, or deadline is uncertain, report `ARM_OUTCOME_UNKNOWN` until a scoped close establishes the final native gate state. The legacy 16 byte `SOGA` opcode 3 path remains for existing users, but both dispatch through one routine to prevent predicate drift.
* Fault `CLOSE_SCOPED`: variable body, `SOPC` magic, version `1`, opcode `1`, 32 byte independently provisioned fault capability, nonzero desired generation, then expected role (`u8`, exactly `NECK=3`), expected incarnation length (`u8`) and bytes, expected boot length (`u8`) and bytes. Body length is `49 + incarnation_length + boot_length`, from 51 through 177 bytes. After an exact expected OS peer match and syntactic frame validation, a capability mismatch returns without touching the gate; a matching capability reaches the gate's atomic role/incarnation/boot comparison **before** any latch or gate mutation. The length framed `SOPD` version `1` reply carries status (`ARMED_CLOSED=0`, `NOT_ARMED_CLOSED=1`, `REJECT_GENERATION=2`, `REJECT_IDENTITY=3`), role, zero reserved byte, desired generation (`u64`), stored generation at the linearization point (`u64`), and the same two length prefixed immutable service identity strings. Maximum reply body is 154 bytes. The native close action happens before the reply is written. A missing reply, including a timeout after the action, remains unproven to Python. Both success statuses require a complete authenticated reply and a final deadline check. Neither status is encoded as the old `SOGA` ACK.

Use exact frame lengths, reserved zero checks, version checks, 1–64 byte printable ASCII identity checks, and a finite maximum before allocating or parsing. Update the compiled close transport to ABI version 2 with an explicit `BOOTSTRAP_IDENTITY` operation, a `CLOSE_SCOPED` operation, expected role/incarnation/boot inputs, and at least a 154 byte reply buffer. On the fault socket, allow the new maximum 177 byte request only for a validated `SOPC` header; do not raise the old close parser's 62 byte limit. The main Python transport accepts at most 236 bytes for `PREARM_STATUS` and exactly 104 for diagnostic ARM. Resolve and validate ABI and copied library provenance before activating safety, as `NativeRevocationClient` does today. The primary fault channel remains read only bootstrap plus close: it cannot parse ARM, reservations, goal CDR, or ingress queries. Its connection bound remains 2 ms in the ordinary profile; the existing sealed simulation policy's 50 ms bound remains unchanged. Each main exchange keeps the existing 50 ms connection ceiling, including path and peer checks, send, reply, and final check. No phase refreshes the clock within an exchange.

## Python startup and fault flow

`head_execution_runner._drive_loop()` passes its existing `stop_requested` SIGTERM event to `HeadLocalRuntime.arm(cancel_event=...)`. The signal handler still only sets that event. The runtime starts its watchdog and both independent stop workers before bootstrap, sets one absolute monotonic startup deadline at `start + 2.0 seconds`, and runs the existing Python prearm guard. It then makes one authenticated fault socket `bootstrap_identity()` query and pins the returned role/incarnation/boot in a private startup field separate from `_armed_identity`. `HeadReservationAuthority.prearm_status('neck')` validates the main reply's peer, capability, role, requested and stored generations, and requires its identity to match this pinned fault identity. It returns the typed controller result without setting `_armed`. If bootstrap never returns a validated identity, ARM is prohibited and native closure stays unproven under the stated bootstrap policy.

On a valid `NOT_READY`, wait until at least 125 ms **after that query's reply** before the next query, using `cancel_event.wait(timeout)` so SIGTERM interrupts the wait. This interval exceeds a full 51 sample, 100 ms continuous simulation window even if the previous query collided with `observe()`. The next query still makes a fresh native check; a passing result is never inferred from the wait. Poll only `NOT_READY` caused by a controller stop proof. Terminal gate/scope rejects, transport failures, identity changes, or lost local guard end startup. The finite two-second deadline gives at most 16 ordinary polling opportunities, including the first, and no unbounded loop. Native wrapper/proof execution and POD copy must be short, with no allocation or logging under the witness lock. This schedule reduces repeated collision risk but does not prove zero observer effect: test measured lock losses and latency at 500 Hz, including deliberately aligned queries. In a deterministic 500 Hz test with one query/update collision and otherwise valid observations, the next query after the 125 ms wait must return `READY`; sustained starvation fails the design gate and requires a reviewed read-strategy revision, without weakening the stop predicate. No query creates a reservation, changes `_armed`, or allows a search tick.

Every startup exchange uses one effective absolute deadline: `min(exchange_start + configured_exchange_bound, startup_deadline)`. The main bound remains 50 ms. The fault bootstrap and later fault identity use their existing configured bound, 2 ms in the ordinary profile or the sealed simulation policy's 50 ms, never a larger value. A reduced remaining startup budget is passed to the compiled transport for that call without changing its frozen configured limit; it cannot refresh the budget on delayed native entry. Check the overall deadline and cancellation before and immediately after bootstrap, each readiness query, diagnostic ARM, and each post-ARM identity query. Do not start a new exchange when the overall deadline has expired. Recheck after local validation and before final runtime-ready publication. OS descheduling can delay a return, but a late return cannot authorize readiness or search. There is no claim that reserving three nominal exchange budgets alone bounds scheduling or validation work.

On a valid `READY`, recheck cancellation, local guard, scope, and the overall deadline, then send one opcode 6 ARM with the current intended generation. The native before and after proofs remain decisive; readiness is not cached as proof for ARM. `STOP_BEFORE`, `GATE_ARM`, and `STOP_AFTER` replies become distinct `HeadReservationAuthority` failure codes with the native evaluation record attached. The runtime does not call `identity()` or permit ingress after an ARM refusal. On ARM ACK, it retains today's main identity query and independent fault identity query, compares both with the pinned bootstrap identity and frozen local scope, and then, under its state lock, checks cancellation and the overall clock before setting `_armed_identity`. It checks again before returning startup success; the runner checks again before `after_arm`, after `after_arm`, before capture/owner activation, and before entering the search loop. A late deadline or cancellation at any of these points prevents search and hands `runtime.stop('sigterm', ...)` or a named startup expiry to the two existing stop workers. The runner's cancellation path is separate from the generic native startup fault handler, so a SIGTERM is not mislabeled as `HEAD_LOCAL_RUNTIME_NATIVE_STARTUP_FAILED`. No runtime/state lock is held during socket calls, interruptible waits, or stop/fault callbacks.

A cancellation during an in-flight ARM cannot prove that ARM was never processed. After the bounded exchange returns or fails, the runner stops the attempt and uses scoped close with the pinned identity; it never activates the owner. Likewise, expiry after ARM was sent, including a timely ARM reply followed by delayed identity validation, is named `HEAD_STARTUP_DEADLINE_EXPIRED` and closed as an uncertain or known armed scope as appropriate. A timeout or incomplete ARM reply is labeled `ARM_OUTCOME_UNKNOWN` until a validated scoped close establishes the final native gate state. The stop workers remain live during all startup waits. Physical Stop, native close, and retirement remain independent evidence.

The stop worker calls `NativeRevocationClient.close_scoped_strict(expected_identity=pinned_bootstrap_identity)` for this Head scope, including when `_armed_identity` is absent. It sends the expected identity in the authenticated request and accepts `ARMED_CLOSED` or `NOT_ARMED_CLOSED` only after the native gate has compared it before mutation and the compiled transport validates the full fault peer, capability, generation, frame, response identity, and deadline. `NOT_ARMED_CLOSED` is a native gate seal for the desired generation's never established state. It is not an ARM ACK and is valid only when the reply reports stored generation zero. `ARMED_CLOSED` requires stored generation equal to desired. A different stored generation or incarnation, ambiguous receipt, or transport error leaves native seal `UNPROVEN`; the worker still pursues physical cancel and raw Stop independently. The final attempt receipt records the native status, requested and stored generations, role, incarnation, boot, source process identity, monotonic request/ACK times, transport origin, and the separate physical Stop and owned child exit evidence. `UNKNOWN` remains the verdict when required closure or physical evidence is missing. No close result may rewrite the original historical case `900009` record.

## Failures and diagnostics

Persist the authenticated `ProofRecord` and request/reply times for **every** valid readiness poll, bounded by the two-second, 125 ms schedule, and for the single diagnostic ARM reply. Each record carries its evaluation ID, exact wrapper branch, current witness rejection, historical reset reason, count, lock losses, indices, and first/last sample times from the call that made the decision. Persist the status and native gate reason separately. A valid ready response followed by `STOP_BEFORE` is a race or changed witness state; report both evaluation IDs and records. Native logs identify the same phase and bounded record on refusal only. A gate ARM failure reports its own generation, clock, or latch branch where available; do not label it a witness failure. A missing reply cannot be replaced by a later witness snapshot or a native stderr line as an authenticated Python receipt. If diagnostics cannot distinguish an internal branch, use `UNCLASSIFIED`, never a guessed cause.

The earlier 50 ms ARM transport overrun, `HEAD_ADMISSION_RESUME_FAILED`, and pre-ARM environment scope failure remain separate branches. The protocol changes do not claim to repair them. The Python startup bound may turn sustained lack of native readiness into a named `PREARM_READY_DEADLINE` refusal before any ARM. That refusal still triggers independent stop and scoped close; it cannot be counted as a successful search.

## Verification and acceptance

Native cases cover 51 continuous 2 ms samples and exact reference equality; every checked witness rejection and last reset branch; controller inactive, joint scope, and active or nonholding goal before and after a passing witness; `READY` without gate mutation or ingress; not ready then ready; and records whose IDs, counts, loss counter, indices, and timestamps still match the evaluated call after later observations. A current `INCOMPLETE` result must coexist with a distinct historical invalid-sample reset reason. Query and `observe()` contention at 500 Hz must recover a full window after contention stops; deliberately aligned 125 ms queries must expose and quantify any lost samples and startup latency. Fault close must proceed while a witness lock is held, with no gate/witness lock cycle. If these tests show sustained starvation, the polling strategy is not accepted.

Protocol cases cover peer, capability, role, identity, generation, exact length, reserved bytes, version and truncated reply; readiness invalidating before ARM; each before/gate/after ARM refusal; ARM ACK with identity agreement; no ARM retry; and cancellation at bootstrap, not ready wait, after ready, in-flight ARM, both identity queries, and before owner activation. ## Implementation boundary and open review choices

The affected source surfaces are `controller_stop_witness.hpp`, `broker_owned_trajectory_controller.*`, `controller_goal_admission.hpp`, `controller_reservation_protocol.*`, `controller_reservation_socket.*`, the Head native revocation transport and ABI, `HeadReservationAuthority`, `HeadLocalRuntime`, `NativeRevocationClient`, `head_execution_runner.py`, and their focused tests. The runner remains the single startup owner; provider construction continues to provision the two distinct capabilities and the same native process identity. No source or test file is changed by this design. The concurrent diagnostic-only witness work in the same worktree is a separate task; its added `checked_proof()` and bounded `Snapshot` are the current source contract this spec consumes. That work does not implement or approve the new readiness or close protocol.

The recommended choices are fixed in this candidate: a 2.0 second absolute startup cap, at least 125 ms between responses and subsequent readiness polls, and diagnostic ARM opcode 6 with a typed 80 byte evaluation record. The 2.0 second cap is a simulation policy choice, not a claimed measured startup distribution. Native stderr alone cannot provide an authenticated per-attempt refusal receipt. Written review and approval of this revised architecture remain required before protocol implementation.
