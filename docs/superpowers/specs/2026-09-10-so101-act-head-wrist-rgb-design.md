# SO-101 双 RGB 视角 ACT、颈部搜索与随机示教设计

日期：2026-09-10

更新：2026-09-11，补齐动作执行、碰撞与释放门控、撤离终态和闭环验证集合；ACT 单次运行上限为 2 分钟。

状态：已确认方案的设计汇总，供实现与审阅使用。本文不代表相机、控制器、数据集或 ACT 已完成运行验收。

## 1. 目标与课程范围

在 MuJoCo 中为 SO-101 增加 head 与 wrist 两台普通 RGB 相机。独立搜索状态机控制单轴颈部 yaw，发现杯子后锁定头部；ACT（Action Chunking with Transformers）根据双相机 RGB、机械臂状态和头部朝向控制手臂与夹爪。MoveIt 2 提供示教动作，杯子在经过验证的可抓取区域内连续随机分布。

保留 V5-T001～V5-T005 的 Agent、感知与几何规划链路。本文对应 V5-T006～V5-T010 的 ACT 支线，后续实现属于 `src/so101_demo_py`，Teleop 集成属于 `src/so101_teleop`。实体机械臂迁移属于 V6，仿真验收不能替代实机验收。

课程当前“至少 50 个有效 episode、至少 3 个位置”是原始最低要求。本设计采用更严格的数据方案：至少 50 个训练、10 个离线验证、10 个离线测试 episode，另设至少 10 个可重复使用的闭环验证初始条件，以及至少 10 个无专家示教的封存闭环测试初始条件。本文更新设计口径；公共课程条目与个人进度不随本文自动修改。

## 2. 已确认决策

| 项目 | 决策 |
| --- | --- |
| ACT 图像输入 | 仅 `head_camera` 与 `wrist_camera` 的 RGB |

| task_camera | 保留既有 RGB-D 教师链路，不进入 ACT 输入 |

| neck 控制权 | 独立搜索状态机 |

| 杯子位置 | 可抓取区域内分层、连续随机采样；空间隔离数据划分 |

## 3. 系统分工与信息边界

```text
head RGB → 轻量杯子检测器 → HeadSearchController → neck controller
                   │
                   └→ TARGET_LOCKED + 方位结果 → neck 保持

head RGB + wrist RGB + q1…q6 + neck 朝向
                   ↓
        RgbObservationSynchronizer
                   ↓
              ActPolicyRunner
                   ↓
             ActSupervisor
                   ↓
          ActExecutionAdapter
                   ↓
       arm/gripper controllers → MuJoCo

示教时：task_camera RGB-D → 感知/tf2 → MoveIt 教师
                                      ↓
                               执行命令记录
                                      ↓
双 RGB 与实测关节 → EpisodeRecorder → ACT 数据集
```

ACT 不读取 `task_camera`、Depth、`/cup_pose`、TF、Planning Scene、物体真值、接触或教师内部阶段。教师轨迹经过转换后是训练 action 标签，不作为 observation。运行基础设施仍可维护 TF，不能把“不输入 ACT”误解为删除系统 TF。

第一版教师继续使用已有 `task_camera` 感知链路。真值用于初始场景生成、独立可达性审计、数据质量检查和仿真监督。若未来采用真值驱动的教师，应单独标记数据来源，不能混写为相机驱动教师。

仿真监督器允许读取接触、物体抬升及放置结果，用于停止、持物判断和结果验收。这意味着最终结果属于“RGB ACT + 搜索控制器 + 仿真监督器”的混合系统；不能称为整个运行系统只依赖 RGB，或直接宣称可迁移到无接触传感器的实机。监督器不得把真值转换为 ACT 目标或替 ACT 完成抓放动作。

## 4. 机构、相机与视野

```text
固定基座参考系
  ├─ SO-101 手臂 → gripper 刚性安装面 → wrist_camera
  └─ head_mast → neck_yaw_joint → head → head_camera
```

head 支架与机械臂基座保持固定关系，安装高度、水平偏置和俯角由视野预检确定。wrist 相机安装在随腕部转动的刚性部件上，不挂在活动夹指上。新增支架和相机外壳需要加入碰撞几何；机械臂规划、reset 与 MuJoCo 接触检查均应识别它们。

相机光轴斜向下，不能与 yaw 轴重合。单轴 yaw 只调节水平方向；锁定条件采用“水平居中 + 垂直有效视区”，不要求通过 yaw 把目标移到图像二维中心。固定俯角无法覆盖的区域必须在采样前排除或重新调整安装参数。

两相机首版统一为 `640×480`、RGB、10 Hz。CameraInfo 可供几何校验与搜索控制使用，但不进入 ACT。head/wrist 不创建 Depth topic。已有 CameraPlugin 的 RGB-D 默认行为需要增加逐相机 RGB-only 选项，并保持 task_camera 的既有 RGB-D 行为。

新增模型采用显式 ACT 场景/配置入口，保留原有 V5 几何规划入口。MJCF、URDF、关节映射、控制器、keyframe 和 reset schema 同步变更；所有访问通过关节名称解析，避免新增 neck 导致 qpos 索引错位。颈部使用独立 controller，不加入手臂 MoveIt planning group。

视野预检覆盖搜索、接近、闭合、抬升、搬运、放置与撤离。至少确认：head 能覆盖候选杯子位置；wrist 在接近阶段有有效目标细节；锁定后的双视角对放置区提供足够信息。单个时刻遮挡允许存在，不能把长期不可观测场景批量加入正式数据。

## 5. 搜索、锁定与控制交接

搜索采用固定状态机，不训练搜索策略，也不调用 ACT 或 LLM 决定转头动作。轻量物体检测器只读取 head RGB，输出杯子类别、检测框和置信度；具体模型及权重在 head 视角验证后冻结，本设计不预先指定型号。搜索不读取 Depth、杯子真值或 `/cup_pose`。

搜索按以下固定流程执行：

1. 手臂在安全观察姿态保持，neck 从配置起点沿固定方向扫描，先检测起点视图。
2. 没有合格候选时，neck 转动固定角步长，待运动停止并稳定后再读取新鲜图像。扫描角步长不超过水平视场角的一半，并通过工作区投影验证实际重叠。
3. 检出唯一合格候选后暂停粗扫描，用检测框中心相对图像水平中心的误差控制小角度 yaw 修正。比例增益、单次修正上限、死区与电机方向在预检中确定；每次修正后停稳再检测。
4. 满足连续稳定居中条件后锁定 neck，返回杯子方位。若微调时丢失候选，则在剩余扫描预算内恢复扫描，不沿用旧检测框继续转动。

一次粗扫描最多覆盖一整圈，微调另设次数与累计运动量上限；二者共同受总搜索时限约束，禁止无限扫描或居中振荡。单轴 yaw 的“居中”只指水平居中，垂直方向仍须落在固定俯角覆盖的有效视区。

```text
SAFE_OBSERVE → SEARCH_CUP → CENTER_CUP → TARGET_LOCKED → CAMERAS_STABLE
                                             ↓
                                      ACT_PICK_PLACE
                                             ↓
                                  RELEASE_CONFIRMED
                                             ↓
                                       ACT_RETREAT
                                             ↓
                              VALIDATE_FINAL_PLACEMENT → DONE
```

锁定需要唯一杯子候选、冻结的检测阈值、足够像素面积、有效垂直视区、水平中央窗口，以及至少 3 帧新鲜且身份一致的稳定检测；此时 neck 已停止。二维居中仅证明目标可见，不证明三维可达。学习策略的部署范围由预先验证的固定工作区限定，错误或越界动作仍由监督器拒绝。

多帧检测不能仅按“类别相同”关联，需使用检测位置/外观连续性与 neck 角度变化检查。目标歧义返回 `TARGET_AMBIGUOUS`；一圈结束无候选返回 `TARGET_NOT_FOUND`；图像过期停止 neck。检测模型需要在 head 视角单独验证，task_camera 上的既有指标不视为新视角资格。

neck 的完整扫描角使用连续累计角度；ACT 输入使用 sin/cos 编码。不能用取模后的角度差判断是否扫完一圈。搜索起点、方向、停留时间、每次锁定角和失败原因均记录。

### 方位返回契约

搜索结果供状态机交接、界面显示与审计使用，不增加 ACT observation 字段，也不作为 MoveIt 的三维抓取目标。

| 字段 | 约定 |
| --- | --- |
| `found` / `status` | 仅完成稳定锁定时为 `true` / `TARGET_LOCKED`；其余返回明确状态 |
| `bearing_rad` | 杯子检测框中心对应视线在基座 XY 平面上的方位，范围 `[-π, π)`，从基座 +X 向 +Y 为正 |
| `frame_id` / `ray_origin_frame_id` | 分别记录方向表达所用的实际基座 frame，以及视线起点所用的实际 head 相机光学 frame |
| `neck_yaw_rad` | 与检测图像时间对齐的 neck 实测角，保留连续累计值，不使用命令目标角冒充反馈 |
| `confidence` | 最后一个合格锁定帧的检测置信度，不代表方位误差或抓取成功概率 |
| `timestamp` / `attempt_id` | 最后一个合格锁定帧的仿真时间，以及本次搜索标识；用于拒绝过期和跨 attempt 结果 |

方位计算使用去畸变后的检测框中心、相机内参和该帧时刻的相机安装旋转及 neck 反馈：先还原相机视线，再旋转到基座坐标轴，最后用 `atan2(ray_y, ray_x)` 计算水平角。固定俯角和安装旋转必须参与计算，不能直接把像素偏移当成 neck 角度；水平投影过小或标定/反馈缺失时拒绝发布有效方位。

这里返回的是“从相机光心看向杯子的视线方向，以基座坐标轴表达”。相机存在水平安装偏置时，它不等于“从基座原点指向杯子的精确方位”。首版不估计距离，也不使用桌面交点或深度补成 XYZ；仅凭这个结果不能生成三维抓取位姿。

只有 `found=true` 且状态、时间戳、attempt 与 neck 锁定反馈全部有效时，结果才允许用于交接。失败、reset、重新搜索或锁定失效时，`found=false`，`bearing_rad` 与 `confidence` 置空；neck 反馈如仍有效可保留作诊断。消费者还须按配置的新鲜度上限拒绝过期结果，不得复用上次成功方位。进入 ACT 后，搜索结果只作为该次交接记录，抓取前的持续目标丢失按第 10 节处理。

进入 ACT 前，取得手臂控制权并确认教师/其他动作客户端没有活跃命令。neck 保持其锁定角；意外漂移超过容差应停止 ACT。恢复完成后才能重新交接给搜索控制器。搜索控制器没有手臂命令接口，ACT Runner 没有 neck 命令接口。

## 6. Observation 与 action 契约

| 字段 | 形状及语义 |
| --- | --- |
| `observation.images.head` | RGB；存储图像为 H×W×3，模型预处理转换为 3×H×W |
| `observation.images.wrist` | 同上；相机键与预处理配置冻结 |
| `observation.state` | 8 维向量：`[q1,q2,q3,q4,q5,q6,sin(neck_yaw),cos(neck_yaw)]` |
| `action` | 6 维绝对位置目标：`[q1_target,…,q6_target]`，单位 rad |

`q6` 为夹爪关节角。原始状态与标签按固定关节顺序保存，归一化统计只由训练集计算。原始 neck 弧度、实际时间戳、相机内外参与数据版本保存在审计侧，原始 yaw 不重复加入模型输入。

控制频率与图像频率分开描述：ACT 以 10 Hz 的动作时间网格输出目标序列，底层 controller 可以以更高频率插值。chunk 长度、实际执行前缀长度与是否使用 temporal ensembling 在训练配置中冻结；不能默认整块动作执行完才检查输入。监督器应能中止已排队动作，独立于推理是否及时返回。

`ActExecutionAdapter` 将同一批次的 6 维动作拆为五维手臂与一维夹爪轨迹。两者携带相同的 session、attempt、动作序号、观测时间和绝对目标时间，使用共同的未来起始时间及相同时间网格。必须在起始时间前确认两个 controller 均接受目标；任一拒绝、接受超时或时间偏差超限，取消双方并确认停止，禁止单侧继续。两个独立 controller 不具备原子提交保证，预检必须验证部分接受时的停止路径及所需提前量。

首版只提交当前获准的执行前缀，其余 chunk 留在 Runner。新前缀必须与已执行边界衔接；替换时核对双方活跃 goal 与动作序号，使旧前缀失效，并重新检查实际插值路径。迟到预测不能通过整体平移时间继续执行：若无法在目标时刻前完成双侧接受和安全检查，拒绝该前缀并停止。停止、reset 或 attempt 结束后返回的异步推理结果一律丢弃。temporal ensembling 若启用，先按同一绝对目标时刻合成，再做动作和路径校验。

每帧使用统一仿真时间记录 head、wrist、关节状态和 neck 状态；动作网格也使用仿真时间。单调墙钟用于性能统计、ACT 的 120 s 运行上限和通信看门狗，避免仿真暂停后超时机制失效。reset 后生成新的 episode/session 标识，拒绝上轮缓存。采用因果采样：observation 来自决策时间或此前的有效样本，不使用未来状态补输入。双相机优先渲染同一 physics snapshot；不同快照须通过显式同步容差。

缺帧不能简单删除后拼成伪连续 10 Hz 序列。原始证据保留时间空洞；首版将影响 action chunk 连续性的 episode 标为无效并重采。重复时间戳是异常，静止场景连续帧像素相同不自动判为重复帧。

## 7. MoveIt 专家动作与示教录制

搜索和示教使用与 rollout 相同的头部锁定流程，ACT episode 从 `TARGET_LOCKED`、相机稳定后开始。搜索日志单独保留，搜索帧不作为 ACT 手臂示教。

动作标签来自控制器接受且实际处于执行中的参考轨迹，必须考虑接受时间、起始时间、插值、取消、替换及手臂/夹爪的不同 goal。优先记录 controller 的 desired/reference；若从 MoveIt 轨迹重建，需验证与 controller 实际插值结果一致，不能仅按轨迹起点做线性插值。

在观测时间 `t_k` 对齐状态后，`action[k]` 表示接下来一个控制间隔要达到的专家参考位置。采样可采用已执行参考轨迹在 `t_k + Δt` 的值，`Δt=0.1 s`；动作生效延迟需测量并记录。相同时间定义必须用于重放与策略部署。该标签使用未来的专家参考作为监督目标是正常的，不允许把未来实测状态当 observation。

状态与动作是不同语义，但在保持姿态时数值可以相等。不能用“二者必须不相同”作为质量规则。独立夹爪 goal 同样转换为该时间网格上的参考位置；没有新 goal 时记录有效保持命令。

```text
RESET → SEARCH → LOCK → 相机稳定 → START_RECORDING
      → MOVEIT_EXPERT → 释放确认 → 专家撤离 → 最终放置稳定检查
      → STOP_RECORDING → QC
```

示教必须覆盖撤离及最终保持阶段，与部署的完成条件一致。不能在杯子刚落桌时截断 episode；放置后的尾段仍记录有效保持命令。首版有效示教从相机稳定后开始，到最终检查结束不得超过 120 s 单调墙钟，并同时保存仿真时长。

每次录制保留原始图像、状态、已接受目标、controller reference、时间戳、场景/代码/模型哈希、随机种子、开始/结束条件和阶段事件。LeRobot 训练视图只导出双 RGB、8 维 state、6 维 action 与 episode/frame/task 元数据。task 文本是数据描述，标准首版 ACT 不因此具备语言条件控制能力。

MoveIt/controller 失败、抓放失败、时间不连续、neck 意外运动、reset 不完整或配置中途变化均不进入成功示教训练集。`DISCARD` 表示从训练集合排除，原始失败证据仍保留。控制器 action 重放与物理结果检查通过后，才批量采集。

## 8. 可抓取区域与连续随机位置

先在桌面构建候选网格，以机器人基坐标系记录杯子 XY；Z 由桌面和杯子几何确定，再经过物理稳定检查。杯子首版保持直立，尺寸、外观、光照、相机安装和放置区固定。

候选点依次检查桌边净空、静态碰撞、pre-grasp/grasp/lift/place/retreat 的逆运动学解、完整碰撞规划、头部搜索可见性以及双视角覆盖。结果形成有效单元集合，不强行拟合成矩形。一个网格中心合格不代表整个单元合格，每次连续采样后的实际点仍需完整预检。规划成功只证明候选可执行，只有实际物理抓放成功才产生有效示教。

有效区域按近/中/远、左右方位、边缘余量与 head 锁定角分层，在各层分配配额，再在单元内部连续随机采样。已有三个锚点保留作回归；训练覆盖连续位置，不能复制同一条轨迹凑数。每层记录候选数、规划拒绝数、搜索失败数、物理失败数和有效数，避免只报告成功样本掩盖区域偏差。

第一阶段随机杯子 XY 与小范围手臂初始关节扰动。头部搜索角度由实际搜索得出，记录其覆盖范围；可测试不同搜索起点，但不随意旋转已锁定视角。起始关节扰动也需验证碰撞与相机可见性。后续再分别增加光照、物体外观和干扰物，按独立数据版本比较。

## 9. 数据划分、规模与泛化测试

在录制前冻结空间单元划分与随机种子。Train、Validation、Rollout Validation、Offline Test 和 Rollout Test 使用互斥初始条件；同一 episode 的任何帧或 chunk 只能属于同一集合。空间相邻单元之间预留隔离带，并验证跨集合的最小实际 XY 距离；仅给网格不同标签不能消除边界附近的泄漏。

隔离距离由有效区域尺度和预期泛化难度确定，写入采样清单并在训练前冻结。若可用空间不足，应减小实验范围或公开调整划分，不能暗中用近乎重合的位置补足配额。不同数据集之间同时核对初始状态和轨迹重复。

| 集合 | 首版最低规模 | 使用规则 |
| --- | --- | --- |
| Train | 50 个成功 episode | 优化权重与拟合归一化统计 |
| Validation | 10 个成功 episode | 离线比较预测动作、选择 checkpoint、调参 |
| Rollout Validation | 至少 10 个固定初始条件 | 可重复闭环运行，选择 checkpoint、执行前缀和监督阈值；不计入最终测试成功率 |
| Offline Test | 10 个成功 episode | 配置冻结后评估动作预测，不能调参 |
| Rollout Test | 至少 10 个独立初始条件 | 无专家示教；独立执行与统计成败 |

Rollout Validation 是开发期间反复使用的仿真场景清单。每个场景保存杯子 XY、手臂初始关节角、头部搜索起点、场景配置哈希与随机种子；每次恢复并核验初始条件后，完整运行搜索、ACT 抓放、撤离和结果检查。固定的是初始条件，不是执行轨迹。记录每次所用 checkpoint、参数、成功或失败原因、耗时与干预，不能只保留调参后的最好一轮。

闭环验证允许用于开发决策，但其轨迹不作为当前训练集新增示教，也不能作为封存测试证据。训练与闭环验证均不得查看封存测试来选参数。正式采集前冻结各集合清单和初始执行配置；后续在闭环验证上调整执行前缀或监督阈值时生成新配置版本，并重新通过控制与标签重放检查。最终测试前冻结 checkpoint 和全部运行参数。

数量是采集起点，不保证 70% 成功率。若增加训练数据，只扩充训练区域与训练种子；观察测试失败后用于针对性训练的数据不再保持测试资格，应另设新的封存测试批次。

V5-T010 使用至少 20 个共享测试场景比较 MoveIt 与 ACT。先冻结 ACT checkpoint、阈值与测试清单，再运行两条路线；此时 MoveIt 对照运行的轨迹属于封存评测证据，不能回流当前模型训练。分别报告空间分布内表现与空间留出表现。

## 10. 停止、抓取监督与恢复

每个 attempt 从进入 `ACT_PICK_PLACE`、发起首次推理之前开始计时，最长运行时间固定为 `act_timeout_s=120`（2 分钟），使用单调墙钟。推理等待、保持、抓放、释放检查、撤离和最终稳定检查均计入；前置搜索另受搜索预算约束。达到 120 s 仍未完成 `DONE` 时返回 `ACT_TIMEOUT`，立即进入停止流程并计为本次失败。不得通过刷新 chunk、短暂停顿或仿真暂停重置计时；停止确认继续执行，即使已超过截止时间。重新搜索后的新 attempt 可重新计时，但不能抹去首次失败，且仍受最多 1 次自动重搜限制。

停止流程为：关闭新动作提交、清空未执行 chunk、取消控制器活跃目标、确认停止/保持状态，再决定恢复。取消请求发出不等于机械臂已停；需读取 controller 回执和关节速度。动作 NaN/Inf、非法维度、越界、过大速度/加速度、过期输入、controller 超时或 neck 漂移均触发停止。首版对非法动作拒绝并留证，不以静默裁剪掩盖策略错误。

提交前，监督器从当前实测状态检查即将执行前缀的实际插值路径，覆盖自碰撞、桌面、head 支架、相机外壳和持物后的碰撞体积；不能只检查终点或借用专家路径的预检结论。检查使用独立的机器人/场景几何，允许接触仅限预先冻结的夹指与杯子、杯子与放置支撑面等接触对及其适用阶段。几何或反馈过期、路径无法验证或出现未允许接触时拒绝并停止。监督器只批准或拒绝，不规划替代动作；有关场景与接触信息不进入 ACT observation。

抓取前 head 持续丢失目标时触发停止；丢失阈值采用时间预算和新鲜帧计数共同约束，不能用旧图累计。抓取监督通过夹爪闭合、双侧接触、微抬升与杯子离台证据确认持物。夹爪闭合接触阶段可能发生遮挡，在预先配置的有界确认窗口内由接触/持物检查接管；超时或持物状态不确定则停止，避免“尚未确认抬升却必须一直看见杯子”的死锁。

| 停止后的状态 | 处理 |
| --- | --- |
| 明确未持物，反馈正常，恢复路径可验证 | MoveIt 恢复到观察姿态，清空策略缓存，再搜索 |
| 明确持物 | 保持夹爪，进入受控放置或人工检查，禁止直接搜索/reset |
| 持物状态未知或控制异常 | 保持停止；必要时暂停仿真并保留证据 |

MoveIt 恢复动作单独计为干预，不得将恢复后的成功算作 ACT 无干预成功。任何重新搜索都建立新的 attempt 标识；首次失败仍计入端到端分母。首版自动重新搜索最多 1 次，之后返回人工检查，防止循环。

抓取后不以检测框消失判断丢杯，持物异常仍触发停止。已持物时，任何会减弱保持或打开夹爪的动作，执行前都必须通过释放门控：杯子位于指定放置区，且已有新鲜证据确认目标支撑面接触和稳定支撑。仅接近桌面高度不算通过；支撑不明或悬空时停止并保持夹爪。开爪判定方向、角度容差、支撑接触与稳定窗口在预检中冻结。若维护了 MoveIt attached shadow，先完成其 detach 再允许物理开爪，shadow 状态不能充当支撑证据。

物理释放建立新的、不可复用的 release epoch，仅使用本次释放后的新样本确认夹爪已释放且无持续指尖接触，之后由 ACT 执行撤离。只有机械臂到达冻结的撤离安全区域并稳定、杯子在指定区域内保持稳定且无持续指尖接触，才进入 `DONE`。撤离失败、碰撞、超时或杯子在撤离后倾倒均不计成功。监督器只判断条件，不生成开爪、撤离或放置动作；MoveIt 代为完成任一步均记为干预。监督依据及其仿真来源必须进入报告。

## 11. 组件与实现位置

| 组件 | 输入/输出与职责 |
| --- | --- |
| `HeadSearchController` | head RGB 的轻量检测结果、相机标定、neck 反馈 → 固定扫描/居中命令、方位结果、锁定/失败事件 |
| `RgbObservationSynchronizer` | 双 RGB 与状态 → 合格观测或明确输入错误 |
| `MoveItExpertActionTap` | 已执行参考与时间 → 6 维标签、重建核验记录 |
| `EpisodeRecorder` | 同步观测、动作与审计流 → 原始 episode、QC 与训练导出 |
| `ActPolicyRunner` | 合格观测与 checkpoint → 定时 6 维动作块 |
| `ActSupervisor` | 输入、动作与监督证据 → 执行许可、停止与恢复交接 |
| `ActExecutionAdapter` | 获准的执行前缀 → 双 controller 定时提交、goal 协调、过期拒绝与停止确认 |

领域契约、应用流程与 MuJoCo/ROS adapter 分层放入 `src/so101_demo_py/src/`，具体文件划分在实现计划中确定。相机/机器人资产、控制参数与搜索阈值分别进入该包的 assets/config。CameraPlugin RGB-only 扩展属于 `third_party/mujoco_ros2_control` 依赖仓；修改后需更新依赖锁与来源证明。Teleop 可提供 Reset、Search、Start Recording、Run Expert、Keep/Discard 等操作，页面不承载高频控制循环。

离线训练环境与 ROS 执行环境通过数据/模型工件连接，固定 LeRobot 与模型版本。已有模型、外部相机检测器或其他相机配置下训练的 checkpoint 均不能直接视为本系统合格产物。

## 12. 参数冻结与实施顺序

以下内容是校准工件，必须在正式采集前通过预检并冻结，不能直接把聊天中的示例当实测值：head 高度/俯角/视场、wrist 安装变换、视野有效区、扫描步长/停留/速度、检测阈值、锁定窗口、丢失持续时间、抓取确认窗口、同步/新鲜度容差、可抓取区域、空间隔离距离、动作速率限制与 chunk 配置。

搜索还需冻结检测器版本与权重哈希、居中增益/死区/修正预算、实际 frame 名称、yaw 零位与正方向、相机内外参、方位有效期和验收角误差容差。方位以相机光心为起点的约定必须随接口保存，不能只传一个无坐标系的角度。

执行预检还需冻结双 controller 提交提前量、接受超时和允许时间偏差、插值与路径检查精度、允许接触规则、开爪判定、支撑与释放稳定窗口、撤离安全区域及最终稳定阈值。ACT 单次运行上限已确定为 120 s 单调墙钟，不作为闭环调参项。

参数生成顺序：模型和 RGB 出口 → 全阶段视野与碰撞预检 → 搜索和控制交接 → 动作记录/重放 → 可抓取区域与数据划分 → 小批 QC → 正式采集 → 训练 → 冻结测试。所有待校准项均由对应预检报告给出明确值、单位、测量依据及配置哈希；未通过该门槛时不得启动正式采集。

## 13. 验收与证据

| 层级 | 必须满足的条件 |
| --- | --- |
| 模型/相机 | head 扫描有效、wrist 随动；两台 RGB-only；安装几何和 TF 一致；task_camera 回归通过 |
| 颈部 | 完整 360°、限速、停止、跨 ±π 正确；单轴水平居中与垂直覆盖分开验证 |
| 搜索 | 无目标、唯一目标、多目标、过期图像、遮挡和扫描超时均有明确终态 |
| 居中/方位 | 左右偏移均能收敛；微调丢失和预算耗尽可终止；角度符号、跨 ±π、安装偏置与固定俯角处理正确；过期/reset/重搜结果不能交接 |
| 控制权 | neck/arm 命令隔离；交接无残留 goal；ACT 阶段 neck 锁定；reset 后缓存失效 |
| 动作执行 | 双 controller 共同时间基准；部分接受可停止；替换无旧动作残留；迟到及跨 attempt 推理结果拒绝 |
| 标签/数据 | controller reference 对齐与重放通过；固定 10 Hz 连续窗口；8 维 state/6 维 action；无禁止输入 |
| 随机采样 | 每个实际点完整预检；分层配额、拒绝统计、空间隔离和种子可复现 |
| 监督/恢复 | 插值路径碰撞拒绝；抓取前丢失可停可恢复；遮挡确认窗口有界；悬空开爪拒绝；释放证据不跨 epoch；持物不明不重搜；干预单独统计 |
| 闭环验证 | 至少 10 个可复现初始条件；保留历次调参结果；与训练和封存测试隔离 |
| ACT | 至少 10 个封存初始条件，独立完整尝试；120 s 内完成抓放、ACT 撤离与最终检查的首次无干预成功率至少 70% |
| 超时 | 始终保持、推理阻塞或仿真暂停时，单调墙钟达到 120 s 均触发 ACT_TIMEOUT；双方停止确认与失败计数有效 |
| 路线比较 | 至少 20 个共享场景；分阶段成功率、总成功率、延迟、重搜及恢复次数 |

同时报告搜索+ACT 的端到端成功率与“已锁定条件下”的 ACT 成功率。前者包含搜索失败；后者必须列出筛选分母，不以搜索成功的少数场景替代完整结果。离线 action loss、controller 成功、视觉截图和物理抓放分别报告。规划或观察姿态恢复不算 ACT 独立动作成功。

搜索单独报告检测与搜索耗时、锁定成功率、水平中心误差和视线方位误差。几何角度校验使用已知投影点检查标定与旋转链路；端到端杯子方位测试则保留检测框中心与杯子参考点可能不重合的误差。仿真真值只作为离线评测依据，不进入检测或居中控制。

目标平台是 macOS 与 ai-station/Linux；新增 RGB-only 渲染、neck/reset、记录重放和闭环分别验证，单平台结果不外推。自动测试覆盖 schema、命令隔离、时间连续性、空间划分和恢复状态；运行验收使用新鲜图像及独立物理证据。本次文档生成不运行这些验收。

在 ai-station 上，数据和持续保留证据归档到 `/data/work/so101-evidence/act-head-wrist/<run-id>/` 并登记；macOS 使用任务明确登记的本地绝对目录。原始证据、训练导出、模型、split manifest、QC、失败记录和封存测试分开保存，用哈希关联。不得把大数据集或运行缓存提交到源码仓。
